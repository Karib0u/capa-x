# Original capa reference results

This dataset records original Python capa 10.0.0 output for every input in
[`scripts/corpus-full-static.txt`](../../../scripts/corpus-full-static.txt):
377 native x86/x64 PE, ELF, and shellcode files from the pinned upstream
test corpus. The selection includes every matching tracked input, without
sampling or exclusions for known failures. .NET, AArch64, dynamic reports,
and feature snapshots are tested separately.

These are reference outputs, not results generated by capa-x. Keep this
dataset fixed while improving the implementation.

The 2026-10-20 capture contains 376 successful documents and one explicit
malformed-ELF rejection. It covers 739 distinct matched rule names,
11,412 rule/sample matches, and 85,783 matched addresses. All 377 corpus
paths are retained; three are aliases of byte-identical samples.

## Contents

- `manifest.json`: all 377 sample paths and SHA-256 hashes, upstream source,
  rules, and testfiles commits, reference version, and per-sample status.
  It also records the Python and extractor dependency versions installed
  for this validation run. Cached results retain their original timestamps.
- `results/<document-sha256>.json.gz`: complete reference result documents,
  including rule source, match addresses, evidence trees, feature counts,
  layout, and library-function metadata.
  Filenames hash the uncompressed stored document; the manifest maps each
  input to its result, including aliases with identical sample bytes.
- `matches.json.gz`: a smaller mapping from sample path to rule name to
  matched address objects. Use this for rule and address regression checks.

The manifest explicitly records any reference analysis failure. A missing
reference output is not an empty match set and must never count as passing.

Only invocation metadata paths are made repository-relative: the sample
path, rules paths, and signature path in `meta.argv`. Timestamps and all
analysis/evidence fields are preserved. Each entry records the SHA-256 of
the original JSON bytes before path normalization and the SHA-256 of its
stored gzip file. Gzip headers use a fixed timestamp for reproducibility.
JSON uses ASCII escapes to preserve Unicode without host encoding changes.

## Reproduce

Initialize the pinned environment according to `CONTRIBUTING.md`, then run:

```sh
scripts/check_env.sh
cargo build --release
python3 scripts/difftest.py --mode full \
  --samples scripts/corpus-full-static.txt \
  --capa-cli target/release/capa-x --jobs 6 --no-rust-cache --no-expected
python3 scripts/snapshot_reference.py \
  --samples scripts/corpus-full-static.txt \
  --output tests/reference-results/capa-10.0.0
```

If original capa fails on an input, provide `--failures PATH` to the snapshot
command. The file must be a JSON object mapping that sample's corpus path to
the observed reference error. The exporter rejects unexplained missing
results, mismatched sample hashes, incorrect reference versions, and
contradictory success/failure records.

## Compare without regenerating the original analysis

Restore the archived reference documents into the differential harness's
cache, verifying their compressed checksums:

```sh
python3 - <<'PY'
import gzip
import hashlib
import json
from pathlib import Path

root = Path("tests/reference-results/capa-10.0.0")
cache = Path(".cache/difftest")
cache.mkdir(parents=True, exist_ok=True)
manifest = json.loads((root / "manifest.json").read_text())
for entry in manifest["samples"]:
    if entry["status"] != "ok":
        print("Reference failure:", entry["sample"], entry["error"])
        continue
    packed = (root / entry["result"]).read_bytes()
    if hashlib.sha256(packed).hexdigest() != entry["result_sha256"]:
        raise ValueError(f"Corrupt reference archive: {entry['sample']}")
    (cache / (entry["sha256"] + ".full.json")).write_bytes(gzip.decompress(packed))
PY
python3 scripts/difftest.py --mode full-exact \
  --samples scripts/corpus-full-static.txt \
  --capa-cli target/release/capa-x --jobs 6 --no-rust-cache --no-expected
```

`full-exact` compares rule names and every matched address. `full` compares
rule names only. Neither mode compares complete evidence trees; those remain
available in the archived JSON for deeper checks. Do not replace these
reference documents with capa-x output or turn current differences into
accepted baseline entries.
